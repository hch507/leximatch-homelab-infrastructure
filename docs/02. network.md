
# 02. Network Design

## 1. 네트워크 구성

LexiMatch 인프라는 역할에 따라 네트워크를 분리했습니다.

| 네트워크 | VMnet | CIDR | 용도 |
|---|---|---|---|
| 직원망 | VMnet10 | 192.168.10.0/24 | 직원 PC |
| 개발망 | VMnet11 | 192.168.20.0/24 | 개발자 PC |
| 서버망 | VMnet12 | 192.168.30.0/24 | DNS / WEB / WAS / DB |
| 개발서버망 | VMnet13 | 192.168.40.0/24 | 개발 서버 |

## 2. IP 구성

### 2.1 게이트웨이 (GW01)
GW01은 각 네트워크의 기본 게이트웨이 역할을 수행하며, 외부 인터넷(WAN) 통신을 위한 NAT 출구를 제공합니다.

| Interface | IP | 역할 |
|---|---|---|
| ens33 | 192.168.164.132/24 | 외부망 (WAN / NAT Outbound) |
| ens37 | 192.168.10.1/24 | 직원망 Gateway |
| ens38 | 192.168.20.1/24 | 개발망 Gateway |
| ens39 | 192.168.30.1/24 | 서버망 Gateway |
| ens40 | 192.168.40.1/24 | 개발서버망 Gateway |

### 2.2 서버 IP 할당 (Static IP)
서버망과 개발서버망의 인프라 서버는 고정 IP를 사용합니다.

| Server | IP | 역할 |
|---|---|---|
| DNS01 | 192.168.30.10 | DNS (BIND9) |
| WEB01 | 192.168.30.20 | Nginx |
| DB01 | 192.168.30.30 | MySQL |
| WAS01 | 192.168.30.40 | Spring Boot |
| leximatch-server-01 | 192.168.40.10 | Development Server |

### 2.3 클라이언트 IP 할당 (DHCP)
직원망과 개발망의 워크스테이션 클라이언트는 GW01의 Kea DHCP를 통해 동적 IP를 할당받으며, 내부 DNS01(`192.168.30.10`)을 바라보도록 구성합니다.

* **직원망 (VMnet10):**
  * Subnet: `192.168.10.0/24` / Gateway: `192.168.10.1` / DNS: `192.168.30.10`
  * Pool: `192.168.10.100 - 192.168.10.200`
* **개발망 (VMnet11):**
  * Subnet: `192.168.20.0/24` / Gateway: `192.168.20.1` / DNS: `192.168.30.10`
  * Pool: `192.168.20.100 - 192.168.20.200`

## 4. Routing / NAT

### Routing

GW01은 각 내부 네트워크에 직접 연결되어 있으며,
각 네트워크의 Gateway 역할을 수행합니다.

| Network | Gateway | GW01 Interface |
|---|---|---|
| 192.168.10.0/24 | 192.168.10.1 | ens37 |
| 192.168.20.0/24 | 192.168.20.1 | ens38 |
| 192.168.30.0/24 | 192.168.30.1 | ens39 |
| 192.168.40.0/24 | 192.168.40.1 | ens40 |

내부 네트워크 간 통신은 GW01의 Routing을 통해 이루어집니다.

예를 들어 개발망의 PC에서 개발서버로 접근하는 경우:

~~~text
Developer PC
192.168.20.101
       │
       ▼
GW01
192.168.20.1
       │
       ▼
Development Server
192.168.40.10
~~~

### NAT

내부 네트워크에서 인터넷으로 통신할 수 있도록
GW01의 외부 인터페이스(ens33)에 MASQUERADE NAT를 적용했습니다.

NAT 대상 네트워크:

| Network | NAT |
|---|---|
| 192.168.10.0/24 | 적용 |
| 192.168.20.0/24 | 적용 |
| 192.168.30.0/24 | 적용 |
| 192.168.40.0/24 | 적용 |

내부 네트워크의 사설 IP는 GW01에서 NAT 처리된 후
외부 네트워크를 통해 인터넷으로 통신합니다.

## 5. DNS

내부 서버의 이름 기반 접근을 위해 DNS01을 사용합니다.

~~~text
DNS Server : 192.168.30.10
Zone       : momantle.internal
~~~

주요 DNS 레코드는 다음과 같습니다.

| Hostname | IP | Description |
|---|---|---|
| dns.momantle.internal | 192.168.30.10 | 내부 Primary DNS 서버 (DNS01) |
| web.momantle.internal | 192.168.30.20 | Nginx 웹 서버 (WEB01) |
| was.momantle.internal | 192.168.30.40 | Spring Boot 애플리케이션 서버 (WAS01) |
| db.momantle.internal | 192.168.30.30 | MySQL 데이터베이스 서버 (DB01) |
| dev.momantle.internal | 192.168.40.10 | 개발 서버 (leximatch-server-01) |

## 6. 네트워크 설계 원칙

### 네트워크 분리
직원 PC, 개발자 PC, 개발 서버, 서비스 서버를 서로 다른 네트워크로 분리했습니다.

역할별로 네트워크 영역을 나누어 서로의 트래픽을 격리하고, 향후 방화벽 정책을 통해 네트워크 간 접근을 제어할 수 있도록 설계했습니다.

### IP 관리
사용자 PC는 DHCP를 통해 IP를 자동으로 받고, 서버는 고정 IP(Static IP)를 사용합니다.

이를 통해 사용자 PC는 IP 관리의 편의성을 확보하고, 서버는 IP 변경으로 인한 DNS 조회 오류, 서비스 접근 불가, 방화벽 정책 불일치 등의 문제를 방지했습니다.

### 중앙 네트워크 관리
GW01을 모든 네트워크의 게이트웨이(Gateway)로 지정했습니다.

모든 네트워크 통신이 하나의 게이트웨이를 거치게 만들어, 네트워크 경로 관리와 통제를 한곳에서 처리하도록 중앙화했습니다.

### 외부 통신
내부 네트워크에서 인터넷에 접근할 수 있도록 GW01에 NAT를 구성했습니다.

내부 사설 IP를 쓰는 PC와 서버들이 외부 인터넷에서 필요한 패키지를 다운로드하거나 외부 통신을 할 수 있도록 주소 변환을 수행하게 설계했습니다.
